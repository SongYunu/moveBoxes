# Easy 집중 실험

[Easy 전용 Colab](https://colab.research.google.com/github/SongYunu/moveBoxes/blob/main/easy/notebooks/moveboxes_easy_colab.ipynb)을 Colab 2026.07 / Python 3.12 / T4에서 엽니다.

코드는 `easy/code/`, 노트북은 `easy/notebooks/`, 검사는 `easy/tests/`에 있습니다.

| 셀 | 실행 내용 |

| 05 | Easy GPU 확인, 원본 데이터, 기존 Easy 성공 시연·모델 가져오기 |

| 08 | 반복별 성적 보기 |

기본 결과는 `run-moveboxes_easy_lab_v1_benchmark` Release에 저장합니다.
`source_run_name='moveboxes_stage_act_v1'`에서 **Easy의 성공 시연과 마지막 모델만** 가져옵니다.
기존 실패 결과, Medium/Hard 학습, 대용량 영상은 입력 복사 대상이 아닙니다. 새 실험의 모델·로그·진행 상태는 별도로 보존합니다.
기존 모델이 없다면 `source_run_name=None, warm_start=False`로 설정해 새 실험을 시작할 수 있습니다.

## 반복 방식

- 모델 크기는 기존 Easy 1.28M을 유지하며, 실행과 같은 zero-latent 경로로 학습합니다.
- 최초 운반 단계까지의 첫 집기 구간을 30% 확률로 따로 표집합니다. 나머지 70%는 복구 시연·전환·전체 작업을 섞어 다음 상자 학습도 유지합니다.
- 2,000 iteration씩 최대 10구간, 합계 20,000 iteration이 기본 한도입니다.
- 각 구간 뒤 실제 환경에서 XYZ 예측 평균화 1/4 두 설정을 각각 8회 평가합니다. 평가 한도는 기존 200스텝입니다.
- 첫 안정적 집기 비율, 두 상자 정답 분류 비율, 전체 분류 정확도를 기록합니다. 집기 사이클에는 같은 상자 재집기도 포함됩니다.
- 최고 모델은 분류 정확도 → 두 상자 정답 비율 → 첫 집기 비율 순서로 선택하고, 이후 학습이 나빠져도 보존합니다.
- 두 상자 정답 비율이 목표 95% 이상인 구간이 2번 연속이면 종료합니다. 4구간 연속 개선이 없거나 총 예산에 도달해도 종료합니다.
  표본이 8회이므로 기본 목표를 통과하려면 그 8회 모두 두 상자를 정답 분류해야 합니다.
- 개발 시드는 50000부터, 별도 테스트는 40000부터, 최종 평가는 70000부터입니다. 최종 평가를 보고 모델을 선택하지 않습니다.

`easy/lab_history.json`은 모든 구간 성적, `easy/lab_best.json`은 최고 모델,
`easy/checkpoints/block_XX.pt`는 고정된 평가 후보입니다. 학습 optimizer/RNG는 `latest.pt`로 이어집니다.
평가 도중 끊겨도 저장된 에피소드 다음부터 재개합니다. 총 예산이나 학습 설정을 바꾸는 실험에는 새 `run_name`을 사용합니다.

Easy는 공식 고정 배치 환경입니다. 시드를 바꾼 여러 번의 성공은 새로운 물체 배치에 대한 일반화 검증을 뜻하지 않습니다.
이 워크플로는 CPU에서 중단 재개·모델 선택·평가 프로토콜을 테스트했습니다. **실제 Easy 성공률 향상은 Colab 실행 결과로 확인해야 합니다.**

## 422 업로드 오류 수정

기존 단계 v1 결과 Release가 첨부 파일 **1,000개**에 도달했습니다.
[GitHub는 Release 하나당 최대 1,000개 파일을 허용](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases)합니다.
수정된 저장 모듈은 950개부터 다음 `-part-002`, `-part-003` Release로 이어 저장합니다.
이전 파일을 삭제하지 않으며 복원할 때 모든 part의 파일 목록을 합쳐 최신 완료 snapshot을 읽습니다.
다음 part에 업로드하다 끊겨도 직전의 완료 snapshot을 사용할 수 있습니다.

기존 런타임의 422 오류는 **02 코드 로드 → 03 연결**을 다시 실행하면 수정 모듈을 사용합니다.
실행 중인 이전 학습 프로세스는 이미 불러온 모듈을 계속 사용하므로, 오류로 중단된 작업은 준비 셀 이후 다시 실행합니다.
새 Easy 전용 노트북으로 전환할 때는 01~05를 실행한 뒤 06을 시작합니다.
