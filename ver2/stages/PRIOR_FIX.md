# 첫 집기 실패: 학습과 실행의 latent 조건 차이 수정

사용자의 `run-moveboxes_stage_act_v1_benchmark` 저장 결과에서 확인했습니다.

- Easy: 12,000회 학습 완료, 빠른 테스트 8회 및 최종 평가 100회 모두 정답 분류 0, 집기 사이클 0.
- 성공 복구 시연 16개는 정상 수집되었습니다.
- 행동 기록에서 모델은 PICK 단계에 머무르면서 첫 상자에 정렬하기 전 아래로 움직였습니다. 단계가 잘못 넘어가서 생긴 첫 집기 실패는 아니었습니다.
- 훈련 loss는 약 0.005까지 내려갔지만 실행 조건 검증 loss는 0.1966에서 0.2691로 올라갔습니다.

기존 구현은 학습 때 정답 행동에서 추정한 posterior latent로 행동을 만들고, 실행 때에는 latent를 0으로 고정했습니다.
그런데 zero-latent 행동 경로를 직접 지도학습하지 않아, 작은 KL 가중치로는 두 경로의 차이가 충분히 줄지 않았습니다.
실제 Easy의 마지막 모델을 같은 별도 시연에서 비교했을 때 posterior 행동 loss는 0.001718, 실행 경로 행동 loss는 0.190676이었습니다.
이는 이 구현에서 확인된 문제이며, ACT/CVAE 전체가 잘못된 방법이라는 의미는 아닙니다.

수정한 기본 `action_training_mode='prior'`에서는 **미래 정답 행동을 모델 입력에 주지 않고 실행과 같은 zero-latent 경로를 직접 학습**합니다.
단계와 완료/복구 분류, 데이터, 모델 크기는 유지합니다. 기존 가중치 형식도 읽을 수 있습니다.
이전 학습을 재현해야 할 때에만 명시적으로 `posterior`를 선택합니다.

4. Medium은 08~09, Hard는 10~11입니다. **기존 Hard 모델이 없다면 보정할 수 없습니다.** Hard 신규 학습은 일반 단계 노트북을 사용합니다.

기존 가중치에서 시작하되 optimizer는 새로 초기화합니다. 같은 보정 셀을 다시 실행하면 마지막 보정 체크포인트에서 재개합니다.
복구 시연 재수집은 필요 없습니다. `repair_iters` 기본값은 2,000입니다.

신규 학습용 일반 단계 노트북은 기본 run_name이 `moveboxes_stage_act_v2`이며, 처음부터 수정한 학습 경로를 사용합니다.
빠른 테스트 또는 모든 튜닝 후보가 정답 분류 0이면 긴 평가를 실행하지 않습니다. 이 때문에 생략된 평가는 최종 점수로 표시하지 않습니다.
0점이어도 의도적으로 전체 평가하려면 `allow_zero_success_evaluation=True`로 설정합니다.

## 확인 범위

실제 Easy 마지막 모델과 저장된 성공 시연을 사용해 CPU에서 300회, batch 16으로 보정했습니다.
같은 held-out 에피소드 표본에서 실행 경로 행동 loss가 **0.194548 → 0.036959**로 줄었습니다.
초기 상태에서 출력한 z 행동은 -0.1630에서 +0.1717로 바뀌었습니다.
이는 오프라인 행동 예측 검증이며 **수정한 모델의 T4 물리 시뮬레이션 성공률은 아직 확인하지 않았습니다.**

테스트는 학습 경로가 미래 정답 행동을 읽지 않는지, 실행 경로와 동일한지, 기존 결과 보존,
가중치/시연 재사용, 중단 재개, 0점일 때 긴 평가 생략을 확인합니다.
