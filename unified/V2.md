## 실패 부분 보강과 연속 학습

- 마지막 실패 단계/미완료 상자와 관련된 기존 전문가 시연의 시간 구간을 집중 표집합니다.
  활성 난이도 표본의 약 70%를 해당 구간에 배정합니다. 해당 시연 구간이 없으면 일반 표집합니다.
- Medium/Hard에서는 배치 약 30%를 이전 난이도에 배정합니다. 집중 표집만으로 과거 동작을 잊지 않게 합니다.
- 500회마다 **학습 중인 모델**을 평가하고 후보 복사본을 만듭니다. 후보가 탈락해도 다음 500회는
  그 학습 모델의 가중치·optimizer·난수 상태를 이어받습니다. 500회 초기 학습을 반복하는 v1 문제를 수정했습니다.
- **최고 모델**은 별도로 보존합니다. 현재 난이도 분류 성적이 개선되고 이전 난이도 성능과 통과 기준을
  유지한 후보만 최고 모델로 바꿉니다. 테스트·패키지는 항상 최고 모델을 사용합니다.
- 새 실패 진단에 따라 집중 구간은 바뀔 수 있습니다. 데이터 파일/성공 메타데이터/분할/학습 설정이 바뀌면
  같은 optimizer로 임의 재개하지 않습니다. 집중 구간 변경만 명시적으로 허용합니다.
- Easy 최대 3,000회, Medium/Hard 최대 각 6,000회, 3구간 연속 최고 기록 개선이 없으면 일단 멈춥니다.
  예산이 남으면 같은 셀을 다시 실행해 학습 중인 모델을 이어갈 수 있습니다.
- 전체 성공이 확인된 시연들 사이에서만 속도 보너스를 적용합니다. 실패 행동은 정답으로 넣지 않습니다.

원본 시연에서 실패 관련 부분을 반복하는 방식입니다. 실제 실패 상태에서 새 전문가 행동을 얻는
교정 데이터 수집/DAgger를 구현한 것으로 해석하면 안 됩니다. 원본에 없는 복구 상태는 별도 교정 자료가 필요할 수 있습니다.

## T4와 저장

153만 파라미터 state 모델, batch 32, FP16 AMP를 유지합니다. 06 셀의 100회 측정 모델은 선택하지 않습니다.
기존 v1의 사용자 T4 측정은 학습 500회 추정 1.6분, 개발 평가 8회 약 2분이었습니다.
새 v2의 Medium/Hard는 평가·이전 난이도 검사·백업을 포함해 실제 측정해야 합니다.

GitHub에는 현재 최고 모델 하나와 JSON/노트북/영상을 저장합니다. optimizer가 든 학습 중 모델은
Colab 로컬에만 남깁니다. **같은 런타임에서는 연속 재개**하고, **런타임이 해제되면 저장된 최고 모델에서
남은 예산으로 새 연속 학습 구간을 시작**합니다. 원격 복원에서 optimizer까지 이어진다고 주장하지 않습니다.
동일 `run_name`으로 01~05를 실행하면 채택 모델과 완료 단계는 복원됩니다.

## 검사

노트북 bootstrap, 원본용/공유 모델용 평가 경로, CPU 학습 2→4 step 재개,

탈락한 학습 모델의 다음 구간 재사용을 검사했습니다. 실제 T4 평가 결과는 07~08에서 확인하세요.
