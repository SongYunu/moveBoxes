# 모든 난이도를 함께 학습하는 Object Attention v1

[Colab에서 실행](https://colab.research.google.com/github/SongYunu/moveBoxes/blob/main/unified/notebooks/moveboxes_joint_scratch_colab.ipynb)

Easy·Medium·Hard 원본 **state 시연 600개**를 사용하고, 모델 하나를 무작위 초기화해 처음부터 함께 학습합니다.
각 난이도의 에피소드 180개는 학습, 20개는 검증으로 분리합니다. `num_demos=None`이므로 시연 개수를 제한하지 않습니다.
전체 데이터는 세 난이도의 state 트랙을 뜻합니다. RGB 트랙이나 이전 실험의 교정 시연은 포함하지 않습니다.
전체 데이터를 한 GPU 배치로 넣는 대신 모든 학습 시연을 표집 대상으로 둡니다.
배치 32에는 세 난이도가 10/11/11개씩 들어가며, 추가 2개를 배정받는 난이도는 무작위로 바뀝니다.
각 난이도 안에서는 모든 학습 시간 구간을 균등 확률로 표집합니다. 한 epoch의 순회 방식은 아닙니다.

## 모델

- **Object-centric action-chunking Transformer**, 1,166,340 파라미터. Diffusion Policy나 기존 단계 고정 모델과는 다른 새 구조입니다.
- 로봇 토큰 1개, 상자 토큰 최대 6개, 수거함 토큰 2개를 spatial attention으로 함께 처리합니다.
- 상자 토큰: TCP 상대 위치, 회전행렬의 두 열, 색상, 색상에 맞는 목적지 상대 위치.
  회전은 quaternion 부호가 뒤집혀도 같은 값이 되도록 변환합니다.
- 모든 상자는 같은 임베딩을 사용합니다. 상자 번호·난이도 ID·슬롯별 위치 임베딩은 없습니다.
  없는 상자는 padding mask로 제외하고, 수거함은 실제 색상으로 연결합니다.
- 과거 8시점의 장면을 temporal attention으로 처리하고, 현재 개별 상자도 행동 decoder가 직접 봅니다.
- 미래 8개 행동을 학습하지만 **한 행동 실행마다 관측을 다시 받고 재계획**합니다.
  최근 2개 예측의 xyz를 평균하고 그리퍼는 최신 예측을 씁니다.
- 기존 집기/운반/놓기 gate나 전문가 단계 정답을 행동 입력으로 사용하지 않습니다.
  행동 chunk도 단계 경계에서 끊지 않고, 에피소드 끝의 없는 미래 행동만 loss에서 제외합니다.
- 액션은 기존 환경의 xyz 이동 + 그리퍼 4차원입니다. 손목 회전 액션을 추가하지 않습니다.

이 구조는 상자 **입력 순서**에 대한 불필요한 의존성을 없앱니다. 실제 공간 배치에 대한 일반화 성능을 보장하지는 않습니다.
원본 데이터의 위치·각도 범위 밖이나 낙하 후 복구는 여전히 어려울 수 있습니다. 새 배치 시연 생성이나 DAgger 수집은 구현하지 않았습니다.
검증 에피소드 분리는 데이터 누출을 줄이지만, 서로 다른 초기 배치 분포를 보장하는 OOD 분할은 아닙니다.

## Colab 실행

기존에 사용한 **런타임 2026.07 / Python 3.12 / T4**를 선택합니다. 새 run 이름은 `moveboxes_joint_object_v1`입니다.
Drive 연결은 필요 없고 03 셀에서 기존 `GH_TOKEN` 보안 비밀 또는 입력창을 사용합니다.

| 셀 | 내용 |
|---|---|
| 01~04 | CONFIG → 코드 다운로드 → 인증/복원 → 의존성 설치 |
| 05 | 세 난이도 state 데이터 다운로드·검증·공동 실험 준비 |
| 06 | 기본 모델 배치 32 역전파, 동일 PT로 54/72/90차원 입력 로딩, 정책 reset 확인 |
| 07 | 공동 학습 30,000 update. 2,000회마다 같은 후보를 세 환경에서 각각 개발 평가 8회 |
| 08 / 09 / 10 | 같은 최고 모델의 Easy / Medium / Hard 별도 테스트 8회 및 영상 |
| 11 | 진행 상황과 최고 모델 결과 |
| 12 | 선택 사항: 동일 모델을 각 난이도 100회 최종 평가 |
| 13 | 세 난이도가 같은 PT를 사용하는 독립 실행용 ZIP 생성·백업 |

처음에는 **01~07**을 실행하고, 학습 완료 또는 한 구간 평가 완료 후 08~10을 실행합니다.
개발 결과가 낮다고 학습을 자동 차단하지 않습니다. 예산 동안 학습 모델은 계속 학습하고 최고 모델은 별도로 선택합니다.
선택 기준은 세 난이도 분류율의 **동일 가중 평균**, 동점이면 최저 난이도 점수와 전체 완주율입니다.
이는 공동 학습용 선정 기준이며 대회 공식 가중 점수로 표시하지 않습니다.
개발 seed는 410000번대, 별도 테스트는 430000번대, 최종 평가는 440000번대로 분리합니다.
환경별 평가 시간 제한은 기존 `max_episode_steps` 설정을 유지합니다.

## 중단·복원·저장

한 구간의 학습과 세 난이도 평가가 끝나면 최고 모델·설정·진행 기록을 **하나의 common snapshot**으로 GitHub Releases에 저장합니다.
테스트 결과·최신 영상과 제출 ZIP도 저장합니다. 최신 snapshot에서 복원하는 학습 모델 PT는 최고 모델 하나입니다.
과거 Release 파일을 삭제하지 않으므로 GitHub에는 예전 snapshot이 남습니다.

같은 런타임에서 07을 다시 실행하면 로컬 `latest.pt`의 optimizer·난수 상태까지 이어갑니다.
런타임이 사라져 01~05로 복원한 경우에는 **선택된 최고 모델**에서 남은 예산을 이어가며 optimizer는 새로 시작합니다.
새 런타임 복원은 마지막 학습 상태의 정확한 재개와 다릅니다. 최고 모델만 복원하려는 기존 저장 요구를 유지했습니다.
첫 구간 평가·백업 전에 런타임이 사라지면 원격에 모델이 없으므로 처음부터 다시 시작합니다.
수동 중단 시 로컬 완료 결과를 보존하지만, 갑작스러운 런타임 소실은 마지막 완료 백업까지만 복원할 수 있습니다.

## 검증과 시간

로컬 CPU에서 자동 테스트 10개가 통과했습니다. 혼합 비율, 에피소드 분리, 단계 경계를 넘는 chunk,
순서 불변성, 없는 상자 mask, quaternion 부호 불변성, 단계 정답 미사용, 학습 후 로딩·재개,
독립 ZIP 로딩, 백업 목록과 관측 진단 호환성을 확인했습니다.
원본 H5 600개 전체를 읽어 기본 117만 파라미터 모델·배치 32로 4 update 학습도 수행했습니다.
같은 PT로 Easy/Medium/Hard 입력 크기와 정책 reset 동작을 확인했습니다.

**T4 전체 학습과 시뮬레이터 성공률은 아직 측정하지 않았습니다.** 06 셀은 메모리·연산 검사이며 집기 성공 시험이 아닙니다.
07에서는 실측 update/s와 남은 학습 시간을 출력합니다. 이 ETA에는 환경 평가·업로드 시간이 포함되지 않습니다.
기본 설정은 개발 평가만 총 360 에피소드이므로 학습 ETA보다 전체 실행은 길어집니다. 최종 100×3 평가는 별도입니다.
`profile='smoke'`는 100 update와 난이도별 2회 개발 평가를 로컬에만 수행하며, GitHub 결과 백업은 꺼집니다.

테스트: `python -m unittest discover -s unified/tests -p test_joint.py -v`.
노트북 재생성: `python unified/code/build_joint_notebook.py`.
