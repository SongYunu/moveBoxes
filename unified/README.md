# T4 공유 모델 커리큘럼

[Colab에서 바로 열기](https://colab.research.google.com/github/SongYunu/moveBoxes/blob/main/unified/notebooks/moveboxes_unified_colab.ipynb)

기존 Medium 선택 모델을 초기 가중치로 사용하는 **state ACT 하나**입니다. 약 153만 파라미터,
batch 32, FP16 AMP, history/action chunk 16입니다. Easy/Medium/Hard 입력을 같은 90차원 슬롯으로
맞추며 난이도별 별도 모델을 만들지 않습니다. 이전 실험 코드는 유지합니다.

앞 단계가 미통과면 학습을 시작하지 않습니다. 테스트 셀은 현재 공유 모델을 진단할 수 있습니다.

## 학습과 채택

- Easy: 전체 에피소드를 평가하고 실패한 상자/마지막 단계와 관련된 전문가 시연 구간을 더 자주 표집합니다.
  이미지 크롭이 아닌 시간 구간 크롭입니다. 관측 이력과 단계·상자 경계 마스크를 유지합니다.
- Medium: Easy 데이터를 재사용하며 명시적 성공 메타데이터가 있는 시연 중 짧은 시연에만 속도 보너스를 줍니다.
  성공 여부가 없으면 해당 시연의 속도 보너스는 꺼집니다. 실패 행동을 정답으로 학습하지 않습니다.
- Hard: Easy/Medium을 재사용하면서 Hard 원본 시연의 배치 변화를 학습합니다.
- 학습 배치의 30%는 다른 학습 대상 난이도에서 표집합니다. Medium 기반을 보존하기 위해 Easy부터 Medium도 재사용합니다.
- 500 update마다 후보를 전체 에피소드로 평가합니다. 평균 분류 점수 상승과 개선 시드 수 > 퇴보 시드 수를
  만족하고, 이전 난이도 성능을 유지해야 채택합니다. 같은 상자 재집기 횟수는 채택 근거가 아닙니다.
- 속도만으로 채택하려면 기준/후보 모두 동일한 개발 시드를 전부 완주해야 합니다.
  실제 마지막 정답 분류까지의 행동 수를 비교합니다. 실패 시 `mean_steps`는 속도로 사용하지 않습니다.
- 개발 8회와 별도 확인 8회에서 Easy는 각각 7회, Medium은 5회, Hard는 4회 이상 **모든 상자 정답**이면 통과합니다.
  이 수치는 실험용 통과 기준이며 통계적 성능 보장이 아닙니다. 별도 테스트·최종 시드는 선정에 사용하지 않습니다.
- 난이도당 최대 6구간(3,000 update), 연속 2구간 개선이 없으면 멈춥니다. 미통과 상태를 통과로 바꾸지 않습니다.
  예산이 남으면 같은 학습 셀을 다시 실행할 수 있습니다. 예산 증액 전에는 영상과 실패 기록을 확인하세요.

이 버전은 기존 전문가 시연의 재가중을 구현합니다. 정책이 실제로 실패한 상태에서 새 교정 행동을 수집하는
DAgger/IWR까지 구현한 것은 아닙니다. 원본 시연에 없는 복구 상태는 이 방법으로 해결되지 않을 수 있습니다.
[논문 근거와 적용 차이](RESEARCH_AND_T4_PLAN.md)를 함께 정리했습니다.

## 예상 시간

새 버전의 T4 전체 실행은 아직 측정하지 않았습니다. 이전 작은 StageACT의 실제 기록은 학습 약
25 update/초, 평가 8회 약 111초였습니다. 이번 버전은 다중 데이터 표집, 반복 프로세스 시작,
보존 검사와 다운로드 비용이 추가되므로 이 속도를 그대로 보장할 수 없습니다.

처음 계획할 여유 시간은 준비 5~15분, Easy 실험 15~45분, 세 난이도의 반복 학습·개발 평가
약 1~3시간입니다. 최종 100회×3 평가를 추가하면 약 1시간 이상이 더 들 수 있습니다.
이는 성공까지 걸리는 시간이 아닌 **설정한 실험 예산의 대략적인 예상**입니다. 통과 실패/조기 중단 시
전 과정을 진행하지 않으며, Hard 평가 속도와 Colab 상태에 따라 예상보다 길어질 수 있습니다.
06 셀이 현재 T4의 학습/평가 실측과 난이도별 최대 예산 추정치를 출력합니다.

## 저장과 재개

별도 Release `run-moveboxes_unified_curriculum_v1_benchmark`에 현재 선택 모델 하나와
커리큘럼/평가 JSON, 노트북, 최신 테스트 영상을 저장합니다. 매 에피소드마다 모든 모델을 업로드하지 않습니다.
학습·선정 구간이 끝날 때 백업하며, 체크포인트와 상태 JSON은 같은 snapshot에 저장합니다.
옛 Release asset을 삭제하지는 않지만 새 런타임은 최신 snapshot에 선택된 모델만 복원합니다.

런타임이 끊기면 같은 `run_name`으로 01~05를 실행한 후 해당 난이도 학습 셀을 실행하세요.
완료된 단계와 채택 모델은 이어집니다. optimizer 전체 이력을 원격 저장하지 않으므로 강제 런타임 종료 시
백업되지 않은 현재 500회 구간은 다시 학습할 수 있습니다. 살아 있는 런타임의 로컬 `latest.pt`는
같은 작업 설정에서 재개에 사용합니다. 구간마다 optimizer는 새로 시작하고 채택 모델에서 보정합니다.

## 검증 범위

CPU 짧은 학습, 입력 54/72/90차원의 같은 모델 로딩, Medium 변환 전후 출력 동등성,
표집 분할과 데이터 체크섬, 이전 단계 미통과 차단, 관측 전용 진단, 단일 모델 ZIP을 자동 검사했습니다.
실제 T4 물리 시뮬레이션 성공률·VRAM은 Colab 06~08에서 확인해야 합니다.
