# v2 Easy 체크포인트에서 Medium 집중 학습

[Colab 바로 열기](https://colab.research.google.com/github/SongYunu/moveBoxes/blob/main/unified/notebooks/moveboxes_unified_medium_colab.ipynb)

T4 / Python 3.12 환경에서 **01~06 준비 → 07 학습 → 08 Medium 테스트**를 실행합니다.
Easy를 다시 학습하거나 원본/변환 비교를 반복할 필요가 없습니다. 새 실험 이름은
`moveboxes_unified_medium_v3`이며 이전 v2 결과를 보존합니다.

## 이번에 바꾼 것

첨부된 v2 실행에서 Easy는 개발/확인/테스트 모두 100%였습니다. Medium은 초기 개발 12.5%에서
1,500회 후보가 18.75%로 개선됐으나, Easy 성능 저하 때문에 채택되지 않았습니다.
이 미채택이 연속 세 번으로 계산되며 학습 루프가 정상 종료됐습니다. 런타임 예외는 아니었습니다.

- v2의 **실제 `easy_initial.pt` 파일을 재변환 없이 그대로** 가져옵니다.
  SHA-256: `7a25c5a68dae13607cf9b9e798d89d5b2a8bda7964393e52d028b6a6982a2435`.
- Medium은 **20,000 optimizer update**, 1,000회마다 평가합니다. 낮은 점수, Easy 점수 하락,
  연속 미채택 때문에 조기 종료하지 않습니다. 수치 오류나 런타임 오류는 숨기지 않습니다.
- 학습 중인 모델은 가중치·optimizer·난수 상태를 이어갑니다. 최고 Medium 모델은 별도로 보존합니다.
- 평균 Medium 분류 점수 상승과 개선 시드 수 > 퇴보 시드 수를 기준으로 선택합니다.
  Easy 결과는 진단에 기록하며 Medium 개선 후보를 거부하는 조건에서 제외했습니다.
- Medium 점수와 각 시드의 정답 상자 수가 같으면 **양쪽 모두 네 상자를 완주한 시드끼리만**
  실제 마지막 정답 분류 행동 수를 비교해 빠른 후보를 고릅니다. 실패를 빨리 끝내는 것은 보상이 아닙니다.
- Easy 원본은 변경하지 않고 별도로 보관합니다. Medium 보정 후 같은 모델의 Easy 성능이
  원본처럼 100%라고 주장하지 않습니다. 09 셀에서 그 차이를 확인할 수 있습니다.

## 이전 시연과 부분 보강 재사용

원본 Medium 성공 시연 200개, Easy 재사용 데이터, 기존 Medium 보정 시연 32개를 함께 사용합니다.
새 교정 시연을 수집하느라 기다리지 않습니다. 저장 자료를 직접 검사한 결과 보정 32개는 모두
199행동 안에 **3개 정답 분류**였으며 4개 완주는 0개였습니다. 이들은 부분 성공 자료로만 학습합니다.
[확인한 snapshot과 체크포인트](medium_v3_input_evidence.json).

활성 Medium 표본 중 약 70%를 실패 단계/미완료 상자와 관련된 시연 시간 구간에 배정하고,
전체 배치의 약 30%는 Easy 데이터로 구성합니다. 일반 Medium 표집에서는 이전 방식처럼
모든 상자의 낮은 접촉 구간을 강조하고 보정 시연의 실제 단계·gate 라벨을 재사용합니다.
관측 이력과 단계/상자 경계 마스크를 유지하며 실패한 정책의 행동을 정답으로 넣지 않습니다.

시간 가중치는 **성공 메타데이터가 있는 시연 중 더 짧은 시연**에만 적용합니다.
원본 200개는 성공 표시가 있지만 모든 시연이 평가의 199행동 한도 안에서 성공한 것은 아닙니다.
따라서 학습 시간 가중치와 최종 199행동 완주 성능은 별개이며, 완주 성능은 실제 평가로 확인합니다.
단순히 기존 시연을 반복하는 것으로 원본 자료에 없는 회복 행동까지 배운다고 보장할 수 없습니다.

| 06 | 학습 전 Medium 개발 점수와 평가 시간 |
| 07 | 최대 20,000회 Medium 학습, 1,000회마다 집중 구간 갱신·평가·백업 |

이번 작업 범위는 Medium입니다. 패키지도 Medium만 포함하며 Easy/Hard까지 통합 검증됐다고 표시하지 않습니다.
v2의 Easy 원본과 Medium에 적응 중인 정책을 현재 보관하고 있으며, 난이도별 자동 전환은 구현하지 않았습니다.

## T4 시간과 재개

사용자의 v2 T4 실측에서 500회 학습 추정은 약 1.2분, 개발 8회는 약 1.9분이었습니다.
20,000회 순수 학습은 단순 환산 약 48분입니다. 새 시연 혼합·구간별 데이터 로딩·평가·Easy 진단·백업을
포함해 **전체 2~4시간 정도를 계획값**으로 잡습니다. 새 구성의 전체 T4 시간은 아직 미측정입니다.
최종 100회는 별도이며 이전 평가 속도 기준 약 20~30분 이상이 추가될 수 있습니다.

새 런타임에서 같은 `run_name`으로 01~05를 실행하면 최고 Medium 모델과 원본 Easy를 복원합니다.
보정 시연도 원본 Release에서 필요한 파일만 다시 받습니다. optimizer는 Colab 로컬에만 있으므로
강제 런타임 종료 시 최고 모델에서 남은 예산의 새 연속 구간을 시작합니다.
살아 있는 런타임에서 같은 셀을 재실행하면 로컬 optimizer까지 이어갑니다.
진행 중인 실험의 모델 구조나 전체 예산을 CONFIG에서 바꾸면 학습 서명 검사에 걸릴 수 있으므로
처음에는 제공된 20,000회 설정을 그대로 사용하세요.

## 확인한 범위

실제 v2 Easy 파일과 보정 시연 32개의 해시·라벨·행동 한도를 검사했습니다.
CPU에서 원본/보정 시연 혼합 학습, 데이터 분할, 연속 재개, 저득점 시 예산 유지,
Easy 점수 하락에도 Medium 개선 채택, 성공 시드끼리만 속도 비교를 검사했습니다.
새 학습의 T4 성능 향상은 아직 측정하지 않았습니다.
